# المساهمة في Mahdi-Editor

شكرًا لاهتمامك! هذه الصفحة تشرح كيف تساهم بفعالية.

## المبادئ

- كل نص يظهر للمستخدم يجب أن يكون **بالعربية** (وأي نص إنجليزي يُضاف يُترجم في نفس الـPR).
- أي واجهة جديدة يجب أن تعمل بشكل صحيح في الاتجاه **RTL** وفي الوضع الداكن.
- لا تُضاف أي خدمة خارجية أو تتبّع دون نقاش مسبق في Issue.

## قبل البدء

1. ابنِ المشروع واختبر تعديلك (انظر [BUILDING.md](BUILDING.md)).
2. تأكد من أن `./gradlew assembleCommunityDebug` ينجح دون أخطاء.
3. اقرأ [REBRAND.md](REBRAND.md) لتفهم هوية المشروع ومعماره.

## تنسيق الشيفرة

- المسافات البادئة: 4 مسافات.
- Kotlin: استخدم `./gradlew ktfmtFormat`.
- XML: منسّق Android Studio الافتراضي بمسافات 4.

لتشغيل التنسيق تلقائيًا مع كل commit:

```bash
git config core.hooksPath .githooks
```

## إرسال التعديل

نعمل بأسلوب GitHub Flow:

1. اعمل Fork للمستودع.
2. استنسخ النسخة إلى جهازك.
3. أنشئ فرعًا جديدًا من `main` باسم واضح (مثل `fix/rtl-drawer` أو `feat/new-theme`).
4. نفّذ التعديلات واختبرها.
5. ارفع الفرع وافتح Pull Request إلى `main`.

يجب أن يحتوي الـPR على:

- وصفًا واضحًا للمشكلة أو الميزة.
- إشارة إلى الـIssue المرتبط إن وُجد.
- تحديث التوثيق إن تغيّرت الواجهة أو السلوك.
- لقطات شاشة عند تغيير الواجهة (يفضّل بالعربية وفي الوضعين الفاتح والداكن).

## تعريب النصوص

- ملف الترجمة: `core/resources/src/main/res/values-ar/strings.xml`.
- أضف المفتاح إلى `values/strings.xml` (بالإنجليزية) ثم ترجمته في `values-ar`.
- حافظ على رموز التنسيق كما هي (`%s`, `%d`, `%1$s`, `\n`).
- استخدم صيغ الجمع العربية الست حيث يلزم: `zero`/`one`/`two`/`few`/`many`/`other`.
